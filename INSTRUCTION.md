# Deployment Instructions & API Keys Summary

This document summarizes all the services, API keys, and environment variables required to deploy the complete Wontu application (both frontend and backend).

## 1. Cloud Infrastructure (Azure)

The application is hosted entirely on Microsoft Azure.

- **Frontend Hosting**: Azure Static Web Apps (SWA)
- **Backend Hosting**: Azure App Service (Linux, PHP 8.4)
- **Database**: Azure Database for MySQL Flexible Server

### Infrastructure Setup Steps:
1. Create the **MySQL Flexible Server** and allow Azure services in its firewall. Note the credentials (`DB_HOST`, `DB_USERNAME`, `DB_PASSWORD`).
2. Create the **Azure App Service**. Set the Startup Command to `/home/site/wwwroot/startup.sh`.
3. Create the **Azure Static Web App**. Connect it to the GitHub repository (main branch). If an automated workflow is created by Azure, ensure it matches or uses the existing `.github/workflows` file.

---

## 2. Third-Party Services & API Keys

You will need accounts and API keys from the following services to enable all application features.

| Service | Keys Required | Description | Where to Obtain |
|---------|--------------|-------------|-----------------|
| **Google Cloud (Maps)** | `GOOGLE_MAPS_API_KEY` | Used by frontend for location picker. Must have Maps JavaScript API, Places API, and Geocoding API enabled. | [Google Cloud Console](https://console.cloud.google.com/) |
| **Google Cloud (OAuth)** | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Used by backend for Google social login. | [Google Cloud Console](https://console.cloud.google.com/) |
| **Resend** | `RESEND_API_KEY` | Used by backend to send emails. | [Resend Dashboard](https://resend.com/api-keys) |


---

## 3. Internally Generated Keys

These keys are generated by the backend application framework and shared with the frontend.

- **VAPID Keys** (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`): Used for Push Notifications. Generate via `php artisan webpush:vapid` on the backend. The public key must be shared with the frontend.
- **Reverb Keys** (`REVERB_APP_ID`, `REVERB_APP_KEY`, `REVERB_APP_SECRET`): Used for WebSockets. Can be generated randomly or via Reverb. The `REVERB_APP_KEY` must be shared with the frontend.

---

## 4. Configuration Locations

Do **NOT** store these secrets in code. They must be configured in their respective environments:

### Backend Configuration (Azure App Service)
Add the following to your Azure App Service **Environment variables** (Configuration settings):
- Database: `DB_CONNECTION`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`
- Laravel Core: `APP_KEY`, `APP_URL`, `FRONTEND_CALLBACK_URL`
- Google OAuth: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`
- Emails: `RESEND_API_KEY`
- Push Notifications: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`
- WebSockets: `REVERB_APP_ID`, `REVERB_APP_KEY`, `REVERB_APP_SECRET`


### Frontend Configuration (GitHub Actions Secrets)
The frontend uses GitHub Actions to inject keys into the production build. Add these to your frontend GitHub repository under **Settings > Secrets and variables > Actions**:
- `AZURE_STATIC_WEB_APPS_API_TOKEN_POLITE_GLACIER_0F247FB00`: The deployment token from Azure SWA.
- `GOOGLE_MAPS_API_KEY`: Your Google Maps API Key.
- `REVERB_KEY`: Must match `REVERB_APP_KEY` from the backend.
- `VAPID_PUBLIC_KEY`: Must match `VAPID_PUBLIC_KEY` from the backend.

### Backend Deployment Authentication (GitHub Actions Secrets)
For the backend GitHub Actions workflow to deploy using OIDC, add these secrets to the backend GitHub repository:
- `AZUREAPPSERVICE_CLIENTID_7B2F0BFF42F24D47A8832833B88A5471`: From your Azure AD App Registration.
- `AZUREAPPSERVICE_TENANTID_1E4FB04532104FDA93785C4ED06637D1`: Your Azure Tenant ID.
- `AZUREAPPSERVICE_SUBSCRIPTIONID_FFC3E817ECBB4107838E6AFAB3992CA2`: Your Azure Subscription ID.

*(The App Registration must have the "Contributor" role on your App Service for deployment).*
